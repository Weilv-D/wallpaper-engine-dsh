# wallpaper-engine-dsh

[English](README.md) | [中文](README.zh.md)

[![Awesome DSH Plugin](https://awesome-dsh-plugin.com/badge.svg)](https://awesome-dsh-plugin.com)

一个 DSH bundle:把本机 **Wallpaper Engine** 壁纸库变成 DSH 的动态背景。视频壁纸在聊天界面背后播放,网页壁纸直接渲染。交叉淡入、液态玻璃面板、随壁纸自适应的可读性遮罩、手动取景、轮播列表、搜索与中英双语界面,集中在设置里的一个专门分区。

## 功能

### 壁纸列表

- 只列出浏览器能真实渲染的类型:视频与网页壁纸。
- 场景与应用壁纸是 Wallpaper Engine 私有的 `.pkg` 包,浏览器无法执行,不列入。
- 每张壁纸按「视频 / 网页」标注类型,全部真实播放。
- 搜索框按标题或创意工坊 ID 筛选。

### 深色材质与可读性

- 材质恒为深色。请将外壳主题设为深色;深色材质以此为前提。
- 遮罩恒为黑色,纯黑壁纸也吞不掉界面。
- 「智能可视」每隔几秒采样一次壁纸的亮度与花杂度(亮度标准差)。画面过亮或过于花杂时,自动加强遮罩。
- 网页壁纸的像素在沙箱中读不到,智能可视改用其预览图作为采样依据。
- 玻璃体色从壁纸采样:色相取壁纸平均色,彩度上限 14%。画面越暗,体色越亮;不透明度由亮度与花杂度共同决定(0.16–0.34)。
- 边缘按「被照亮的柱面」建模:顶边一道高光,底边一道回弹光,左右是压暗的侧壁,外圈一条深色轮廓。边缘光强度随壁纸变暗而增强。
- 镜面高光默认静止;设置里的「指针高光」让一道贴边细光斑随鼠标沿输入卡边缘滑动(顶部 6px 光带 + 底部一道更淡的回弹光,入面不深于 6px,指针离顶边越远越淡;每帧重绘,默认关闭)。
- 输入卡浮在亮画面上时,玻璃内部的暗化层自动升起,上限 35%(HIG 对该场景给出的数值)。

### 折射

- 每块玻璃按自己的像素尺寸与圆角生成位移图,`feDisplacementMap` 位于滤镜链首端:先折射,再模糊。
- 位移在边框处最强,向内衰减到零。边缘因此向内压缩画面,这是液态玻璃的读感来源。
- 尺寸变化时由 ResizeObserver 重建位移图。
- 设置里的「表面折射」开关可整层关闭折射,只剩背景模糊。
- 折射只在 Chromium 系引擎渲染(见「限制」)。

### 档位与覆盖

| 档位 | 表面 | 模糊上限 |
|---|---|---|
| T1 | 裁剪调整条 | 4px |
| T2 | 输入卡、菜单、底栏、新会话按钮 | 10px |
| T3 | 设置弹窗、全页工作台 | 14px |

- 玻璃只做控制层:消息气泡只有体色与边光,没有背景模糊;设置内卡片以半透明令牌软化。
- 菜单、弹窗、浮层面板、底栏走各自的档位;二级菜单(`role="menu"`)按 T2 处理。
- tooltip 只取体色与斜面高光,不做背景模糊。
- 外壳其余浮层消费的 `--dsw-menu-backdrop-filter` 令牌重指向同一套滤镜链;ds-harness-remote 的 `dshRemotePage` 按弹窗材质适配;dsh-better-sidebar 的底栏为 T2 轻玻璃。
- 全页设置页的顶栏(插件页的吸顶条)保持透明:栏内嵌一块裁切的壁纸副本("窗口"),盖在滚过的内容之上、标题/标签之下——壁纸仍然可见,内容不再从线下透出。
- 会话的「轨迹」页整页透出壁纸:宿主给这一页画的是面板底色(不是页面底色),插件只在该视图内把面板令牌换成透明;页面自己不补体色、不加模糊,和对话页一样只剩壁纸与全局遮罩。工具栏、分栏、表格、详情、时间概览随令牌一起透出壁纸;程序源码块保留代码底色(和别处的代码块一致)。

### 手动取景

1. 点「排布」选择基础摆放:填充、适应、拉伸、原始、自由。
2. 点「调整画面」全屏展开壁纸,滚轮缩放,拖动平移。
3. 「自由」模式下可以旋转任意角度(±90° 按钮或 Alt+拖动),缩放范围 0.1–4×。
4. 裁剪范围始终保留画面铺满屏幕;「自由」模式在黑色画布上摆放,保留一小块在屏幕内。
5. 「镜像」水平翻转壁纸,所有排布下可用。
6. 按 Esc 或点「完成」退出,设置保存;「重置裁剪」恢复默认。

### 四个实时滑杆

- **壁纸模糊、暗化、边框、玻璃**,每一步调节立即生效并保存。
- 模糊在原位渲染:任意模糊度下,画面比例、排布与取景完全一致。
- 玻璃滑杆驱动三档滤镜链的模糊上限(4 / 10 / 14px),上限即滑杆顶。归零时滤镜链退为 none,各表面只留体色与边光。
- 边框滑杆驱动玻璃自身的发丝环:默认 0.35 档为基准,拉满约 2.6 倍,归零则环消失、只留斜面高光。宿主自己的控件描边保持原值。
- 壁纸模糊叠加轻微噪声,消除渐变色带;模糊为零时媒体完全绕过滤镜管线。

### 轮播列表

- 可以创建任意多个列表,各自指定壁纸集合、切换间隔(1–120 分钟)与顺序(顺序 / 随机)。
- 当前列表至少有两张可用壁纸时才自动轮转;状态行显示轮转是否正在运行。
- 首次运行自动导入第一个可播放的 Wallpaper Engine 播放列表;其他播放列表可以随时导入到任意列表。

### 资源监控

- 实时帧率读数与低帧率提示。
- 页面隐藏或电量不足(低于 20%)时可以自动暂停视频。
- 系统开启 `prefers-reduced-motion` 时视频默认暂停。

### 中英双语

界面跟随 DSH 的「语言」设置(中 / 英),也可以在面板中手动指定。

### 播放失败自动恢复

- 切换与关闭都以淡入淡出过渡。
- 媒体加载失败时:非强制地重拉当前清单并重挂一次(强制重签会把其他窗口正在播放的 URL 全部杀掉);令牌过期与文件不支持在第一次错误上无法区分。
- 第二次失败若是解码类(解码错误、源不支持,或视频「在播放」却解不出任何帧),该条目记为无法解码:从壁纸网格与轮转列表里移除;若正在显示,切到轮转候选,没有候选就清空图层。
- 其他重复失败改用预览图并在状态行说明;没有预览可用的条目清空选择,避免黑屏。
- 「刷新」清除降级标记、重新扫描并重试原媒体;正在播放的元素直接替换地址,播放进度保留。「无法解码」不会再被刷新复活:判定绑定在文件指纹(大小 + 修改时间)上,只有文件本身被替换或重新编码,条目才会重新回到网格。记为 `*` 的判定(宿主当时无法给出指纹)只在拿不到指纹时隐藏条目;宿主能识别文件后,加载时即释放该判定,仍然播不了的条目会在数秒内被失败阶梯写入真实指纹。2.3.9 及更早写入的判定没有指纹 schema,升级后首次加载时整体丢弃——在插件外修好的文件会回来一次,仍然损坏的文件会在数秒内被重新标记。后台重建清单复用相同 URL,不中断播放。

## 安装

```sh
dsh plugin --profile web add wallpaper-engine-dsh
```

或从源码检出安装(便于开发,改动即时生效):

```sh
git clone https://github.com/Weilv-D/wallpaper-engine-dsh.git
dsh plugin --profile web add link:<克隆文件夹的绝对路径>
```

重启 `dsh web`,在左侧会话列表点「设置」,侧栏选 **壁纸背景**。

## 使用

1. 从缩略图网格选择壁纸,它在界面背后淡入。壁纸库较大时用搜索框定位。
2. **暂停 / 播放** 控制视频;**关闭** 淡出壁纸;**刷新** 重新扫描壁纸库。
3. 用滑杆调节融合效果。壁纸画面复杂时调高 **暗化** 和 **边框**,直到文字清晰。开启智能可视后,这些自动完成。
4. **排布** 决定基础摆放;点「调整画面」直接拖动平移、滚轮缩放。
5. 用 **新建** 创建轮播列表,从网格挑选或导入 WE 播放列表,开启 **自动轮转**。
6. 资源行显示当前帧率与两个自动暂停开关。

所有选择与调节持久化在浏览器的 `localStorage`。

## 桌面端

桌面端与浏览器共用同一前端和同一注入管道。`dsh.client` 声明 `platform: "web"` 即可生效,无需单独的桌面包。

- **Windows**:主窗口不透明,壁纸渲染在 DOM 层。顶部窗口控制按钮条是宿主维护的实色 overlay,插件用一条固定深色(`#1b1b1c`)的短渐变把壁纸衔接过去;进入全屏时自动关闭。
- **macOS**:外壳侧栏为系统原生 vibrant 材质。壁纸在其后播放时,透出的是系统材质而非壁纸本身。
- 系统关闭透明效果(`prefers-reduced-transparency`)时,玻璃与模糊退为实色表面,壁纸保留,可读性由遮罩与实色表面保证。
- 系统开启增强对比度(`prefers-contrast: more`)时,玻璃底色接近不透明,发丝环升级为实线边框,模糊保留。

## 工作原理

bundle 分为两半:

- **宿主插件**:发现 Wallpaper Engine 安装位置(Steam 注册表项、`libraryfolders.vdf`、Windows / macOS / Linux 标准探测路径),枚举默认项目、我的项目与创意工坊目录,只保留浏览器可渲染的类型,并通过同源路由提供数据:
  - `GET /we-background/inventory[?refresh=1]`
  - `GET /we-background/media/<token>[/<入口文件或子资源>…]` —— 支持 HTTP Range,视频可以拖动进度。网页壁纸的 URL 直接定位到入口文件,壁纸内部的相对引用按 Wallpaper Engine 自身的规则解析;媒体响应带 `Access-Control-Allow-Origin: *`,沙箱 iframe 里的壁纸也能读取自己的资源。
  - `GET /we-background/preview/<token>`
- **浏览器插件**:把选中的壁纸渲染在应用框架之下的固定层,提供设置界面。视觉效果读取 DSH 设计令牌。

媒体服务的防护:

- 令牌是无法猜测的 72 位随机值;清单重建时保持不变,只在显式刷新时重新生成。
- 子资源路径先做词法包含检查,再对照真实文件系统复核;符号链接无法指向壁纸目录之外。
- HTML 与 SVG 响应带 `sandbox` CSP,不能以 DSH 源的身份执行。
- 壁纸 iframe 固定使用中性 `color-scheme`,外壳的深色主题不会泄漏进第三方壁纸。
- CORS 通配只允许持有令牌的一方读取其本来就能请求的文件;整个服务只监听本机回环地址。
- 长度不足的响应直接中断,不悄悄截断。
- 清单由宿主缓存 30 秒;安装位置的发现过程异步执行,缓存 10 分钟。
- 本插件不注册模型工具,不占用 prompt。

## 限制

- 场景与应用壁纸不出现在列表中:它们是 Wallpaper Engine 私有的 `.pkg` 包,浏览器无法执行。
- 网页壁纸与页面存储隔离,跨加载保存状态的壁纸无法保留状态。
- 带声音的网页壁纸在与页面交互前保持静默(沙箱文档的音频自动播放限制);依赖 Wallpaper Engine 系统音频输入的壁纸在浏览器中没有信号。
- 视频编码受浏览器解码能力约束:H.264 / VP8 / VP9 / AV1 可以直接播放;H.265 / HEVC 在多数机器上无法软解。检测到「声称在播放但解不出任何帧」时,记为无法解码并从网格中移除;判定绑定在文件指纹(大小 + 修改时间)上,文件重新编码后下次刷新会自动恢复。转码为 H.264 的 mp4 或 VP9 的 webm 即可完整播放。
- 玻璃效果读取 DSH 设计令牌;外壳重构重命名令牌后,玻璃退化为普通半透明。
- 表面折射只在 Chromium 系引擎渲染;Safari / Firefox 解析 `backdrop-filter: url()` 后丢弃整条链,插件按 UA 退回纯模糊配方。桌面端(Electron)不受影响。

## 开发

```sh
npm install        # prepare 钩子自动构建 lib/client.js
npm test           # 纯核心单元测试 + 宿主集成测试
npm run build      # 从 src/client.js 重新生成 lib/client.js
npm run verify     # 在 vm 沙箱中启动产物并断言行为
```

- `lib/core.js`:纯逻辑,有单元测试。
- `lib/index.js`:宿主插件。
- `src/client.js`:浏览器源码,构建产物为 `lib/client.js`,请勿手改。
- `npm run prepublishOnly` 执行完整门禁:test → build → verify。
- 液态玻璃材质的调研底稿(层模型、折射剖面、Chromium 约束,含证据分级与来源)见 `liquid-glass-report.zh.md`。
- 代码阅读规范(先读什么、不变量、常见误读)见 `READING.zh.md`;架构、运行时与交接说明见 `HANDOVER.zh.md`。

## 发布

发布规范见 `RELEASING.zh.md`,由 `scripts/release.mjs` 强制执行。本地一条命令:
```sh
npm run release          # 补丁版本;另有 release:minor / release:major
```

脚本依次执行:预检(分支、工作区、同步、标签一致)→ 门禁(test → build → verify)→ 提升版本号,推送 `main` 与标签。发布由 GitHub Actions 通过 npm Trusted Publishing(OIDC)完成;脚本等待 Actions 结束,确认 npm 的 `latest` 指向新版本,并打印 GitHub Release 地址。
